## Do-Not-Repeat

<!-- Mistakes made and corrected. Each entry prevents the same mistake recurring. -->
<!-- Format: [YYYY-MM-DD] Description of what went wrong and what to do instead. -->

- [2026-07-12] **A PERCENT stat modifier is a silent no-op on a stat whose BASE is 0.** `StatSystem.get_stat = (base + ΣFLAT) * (1 + ΣPCT)`, so a `+15% ATK_SPD` buff on a unit with no base `atk_spd` (0) gives `0 * 1.15 = 0`. Bit the roguelike "Quick Paws" card: 5 of 8 archetypes had no `atk_spd` in `data/combat/archetypes.json` → the card did nothing for them (and those cats sat at the `max(0.5, atk_spd)` cadence floor = slow basic attacks). Fix: every archetype's `advanced` block now defines a base `atk_spd`. RULE: before adding a PERCENT-scaling card/buff for a stat, confirm the stat has a non-zero base on EVERY unit it can target — otherwise use a FLAT modifier.
- [2026-07-12] **GDScript `class_name` static method can't reference class name directly.** When a script has `class_name CardData` and a static method tries `var c = CardData.new()`, the compiler fails with "Identifier not found: CardData" because `class_name` doesn't auto-import the class name to static scope. Fix: use `var c = new()` (instantiates the current class); or use `var c: CardData = self.new()` if you need explicit type. This is a GDScript 4.x quirk; only discovered at runtime (gdtoolkit doesn't catch it).
- [2026-07-11] **BLACK SCREEN from `:=` inferring a Variant.** This project treats GDScript warnings as errors, so any `var x := <Variant expr>` (Dictionary `.get()`, dict/array index, untyped field) is a FATAL parse error → the whole script fails to load → the scene never instantiates → **black screen**. `gdtoolkit` parse/lint does NOT catch it; only Godot does. Concrete case: `var n := {...}.get(rar, 3)` → fix `var n: int = {...}.get(rar, 3)`. RULE: never `:=` from a Variant — wrap in `int()/String()/float()` or annotate `var x: T = ...`. **Always run Godot (not just gdtoolkit) before claiming a `.gd` change works.** A portable Godot 4.2.2 can be fetched to the scratchpad and run `--headless --path <proj> --quit-after N` (stderr shows parse/runtime errors); `tools/capture_runtime_screenshot.ps1 -GodotPath <exe>` grabs a windowed screenshot for visual verification.
- [2026-07-11] Given a web-styled UI spec + reference screenshot, built a full standalone `whisker-realm.html` app before confirming the platform. Wrong — this is a Godot project and the user wanted the in-engine UI improved (`battle_view.gd`). The reference screenshot is a Godot render target. Confirm platform first; treat web-vocabulary specs as design direction, not the deliverable format. (The HTML mock was moved to `research/whisker-realm-web-mockup.html` as a visual reference.)

- [2026-07-12] **GDScript coroutine call without `await` doesn't block — it returns at the first suspend point.** Writing a test/helper function `func f(): ... await get_tree().process_frame ...` and calling it as a bare statement (`f()`, no `await`) does NOT wait for `f` to finish; the caller resumes immediately after `f` hits its first `await`, while `f`'s remainder keeps running "in the background" later. In `tests/roguelike_loop_test.gd` this caused `_ready()` to reach `scene.queue_free()` + print PASS (based on an empty `_failures` snapshot) BEFORE the level-up/card-pick assertions had actually executed — a false-positive PASS with exit 0, plus a later "previously freed" SCRIPT ERROR when the orphaned coroutine resumed and touched the freed scene. Fix: `await` every call site whose callee itself contains an `await`, all the way up the chain to `_ready()`. Also don't assume "one process_frame await = the next `_process()` tick already reacted to my change" — poll a small bounded window (a handful of frames) instead of hardcoding exact signal-vs-`_process()` ordering.

## Key Learnings (pivot recon, 2026-07-12)

- **Two combat drivers, only the LEGACY one grants currency.** `scripts/combat/battle_view.gd` (the pivot's real-time auto-battler) drives its own wave flow and its `_end()` (line 1829) **never calls `GameState.mark_wave_cleared/mark_wipe`** — only `battle_engine.gd` (legacy turn-based) does. So on the pivot branch the player earns NO currency from combat. Any run-reward/meta must be added at a new `GameState.end_run(result, reward)` called from `battle_view._end()`, NOT via `mark_wave_cleared`.
- **Party size is hard-asserted to 4** in `game_state.gd:64-65` (`if party.size() != 4: push_error`), and `_load_party()` (89-98) loads ALL of `starter_party.json`. Starting a run with 1 chosen cat requires relaxing that assert + parameterizing `_load_party`.
- **Recruit-a-cat mid-run, the easy way:** append a `UnitState` to `GameState.party`; the next `_do_wave_swap()` (battle_view.gd:1804-1807) re-reads `GameState.party` via `_spawn_wave()` so the recruit appears next wave — no live re-render. Immediate mid-wave spawn needs `_build_unit()`(495)+append to `_units`+`_build_skill_bar()`(703) and reshuffles placement (`_place_side` 471).
- **Level-up pause:** set `Engine.time_scale = 0` + a new `_phase="levelup"` (combat gates on `"fighting"` at lines 600/605); input isn't time-scaled so a Control overlay stays interactive. Copy the `_open_screen/_close_screen` overlay pattern (1846/1870) on a new CanvasLayer, but dim the FULL rect (their dim starts at `TOP_BAR_H` to keep nav clickable — a modal draft must NOT).
- **Permanent draft buffs reuse the combat core:** `StatModifier.new(key, FLAT|PERCENT, value, source, 0.0)` with duration ≤ 0 is permanent (`stat_modifier.gd:24`); skill upgrades mutate `u["skill"]` (`CombatSkill.cooldown/.skill_ratio/.max_targets`).
